# Canonical session synchronization

After explicit archive cutover, the existing `sync` and consumer-export `import chatgpt|claude` commands send each conversation through the schema-backed `sources.conversation.ingest` operation. Local adapters still discover Claude Code, Codex, Pi, Cursor, and Grok sessions. Consumer imports continue to read downloaded exports; this adds no live account access.

The client connects to the authenticated local service when it is running. With the service stopped it holds one configured engine and the same exclusive operational-store lock for the batch. It never falls back to archive writes after a canonical request fails. Before cutover, legacy synchronization remains available; rollback retains that path.

New canonical conversations use the same UUID and filename calculation as archive exports. Migrated conversations retain their existing IDs, paths, visibility, and original frontmatter, including nonstandard legacy IDs. Each input is bounded to six MiB, and a deterministic ingestion receipt identifies the brain, source, and complete normalized input. The Git commit records the input hash; the durable operational receipt completes only after the projection catches up. An interruption between these steps can replay without another source write. Replaying an older completed input cannot revert a newer transcript.

Synchronization compares content and metadata, rather than skipping records based on a wall-clock watermark. Late sessions and equal-timestamp edits remain eligible. Filesystem and conversation adapter cursors contain per-item fingerprints and are saved after successful persistence. Unknown legacy cursors reconcile the complete source. A failed checkpoint can redeliver committed items without changing their retrieval timestamp or creating duplicate commits.

Current transcripts occupy an explicitly marked managed section. Personal notes outside it survive updates. Editing that section stops subsequent updates with `conversation_user_edit_conflict`; move those edits into Notes and restore the managed transcript before rescanning. On the first changed update of a migrated conversation, Manas retains its entire original body under **Preserved pre-migration content**, including edits that cannot be distinguished from imported text. That historical section remains searchable; inspect it when interpreting older statements. This deliberate preservation is reported as a warning.

Revision checks reject conflicting source changes. A staged write can resume after unrelated Git commits or edits confined to Notes; it cannot overwrite a later imported source revision. Failures are deduplicated in the operational source-failure ledger without storing transcript payloads. A dry run does not stage receipts or mutate the brain.

The operation requires unrestricted local owner administration. Agent MCP clients continue to use authorized memory and context operations. Runtime workers bind source and projection jobs to the configured repository object, tenant, and brain. Repository aliases must resolve to that same directory; foreign roots and managed-source impersonation are rejected. Generic queue creation and scheduling require owner administration, and restricted clients cannot inspect raw job payloads, cancel owner jobs, or run the worker. Legacy brain CRUD, search and expansion, indexing and embedding, extraction, diagnostics, wiki traversal, schema discovery, local source synchronization, generic imports, and note capture also use the configured catalog. Legacy job scheduling and token administration use the same runtime. The legacy `brain migrate` command and TypeScript migration helper use the same resumable archive receipts as `migration preview|resume`; migration remains an offline owner workflow rather than a service operation.


## Local files, generic imports, and notes

`brain sources-sync --source-path <directory> [--source-id <id>] --repo <brain>`, `brain import --file <path> --format eml|mbox|ics|meeting --repo <brain>`, and `capture <markdown> --repo <brain>` connect to the running owner service. They cannot bypass its exclusive store lock. Without the service, these commands acquire the selected canonical store, an explicit `--store`, or `<stateRoot>/runtime` through the configured engine. Keep this state outside Git.

Filesystem checkpoints are scoped to the brain and source ID in operational state. A source ID binds to one canonical directory; choose another ID for a different directory. Unknown old cursors cause full reconciliation. Existing source IDs and document IDs are adopted from provenance, including macOS path aliases and older relative paths. Notes outside the managed section survive. Late files and changed content remain eligible even when their timestamps precede the last scan. A completed cursor is saved only after all records persist and projection work is queued. Interrupted or failed ingestion remains visible in the source-failure ledger; a retry reconciles committed records without duplicate writes. Legacy state files remain available.

Generic import files are additive deliveries rather than complete source inventories. Importing a second file does not mark earlier records stale. Each import is limited to four MiB. These operations require unrestricted local owner administration; scoped MCP clients use memory operations instead. Filesystem roots overlapping the canonical brain and reserved managed-source IDs are rejected.


## Legacy runtime commands and local providers

`brain embed` uses the configured local embedding provider. Legacy `--embedding-endpoint`, `--embedding-model`, and `--embedding-dimensions` flags still work together in standalone mode by configuring that engine invocation. The reranker endpoint/model pair works the same way. With a running service, flags must match its provider configuration; a mismatch returns `provider_config_mismatch` with a suggested fix. Omit flags to use the running configuration. Hosted inference remains disabled.

`brain search --expand` expands lexical terms locally, retaining the shared citation and visibility checks. Explicit reranking uses the configured local reranker without invoking embeddings for a lexical query. `brain related --depth <1-5>` follows wiki links through current authorized pages; a private intermediate page cannot expose a public page beyond it. Typed entity relationships continue to use their evidence-backed traversal API.

`brain extract` uses configured transcription for audio and the existing bounded local file extractors for other formats. Plain extraction also works without selecting a brain. It does not add knowledge records. `brain doctor`, `brain verify`, schema candidates, and source inventory run through the catalog; administration requires unrestricted owner access. Top-level `index` rebuilds the selected canonical projection after cutover, while pre-cutover archive indexing remains available.

Legacy `jobs enqueue-index|schedule-index|list|schedules|cancel` and `auth create|list|events|revoke` connect through the service when available. They retain their flag-based input forms and acquire the same store lock in standalone mode. Catalog job commands with `--input` remain available. Token revocations have durable idempotent administration receipts; client credentials remain separate from the local owner socket token.

A newly created runtime commits its empty brain metadata before serving reads, so setup and search work before the first capture. Reopening an existing brain adds no initialization commit. This bootstrap never imports untracked files or commits an unfinished migration manifest; resume that migration before starting the service. A brain created beneath an existing project checkout gets its own Git repository.

Brain commits preserve configured Git names and email addresses. When a field is missing, the individual commit supplies `Manas` or `manas@localhost` for that field. Manas does not write those defaults into local or global Git configuration. Source provenance and memory actor/session information remain recorded separately from the Git author.


## Offline archive migration compatibility

`brain migrate --from <archive> --repo <brain>` retains its copied/document/commit result fields and adds `migrationId`. It writes the same durable receipt, verified source backup, and canonical provenance as `migration preview` followed by `migration resume`. Pass `--id <migrationId>` with the same source and target to resume the legacy command; `migration status|resume --id <migrationId>` also works. The TypeScript helper accepts an optional `{ stateRoot, receiptId }`; without a state root, it stores receipts in a sibling `.manas-migration-state` directory outside the Git brain.

An empty initialized runtime is a valid target. Preview records its exact Git head; a subsequent unrelated commit stops the import. A target with existing knowledge is rejected, and colliding paths or changed target bytes are preserved. Source and target are canonicalized, and operational state cannot live inside either archive. Copied files come from the hash-verified preview backup, retain original modification timestamps on retry, and are rechecked before the import commit. The original archive is never removed or selected automatically.

Migration holds the configured service ownership lock, so stop that service first. It also holds the same kernel-released mutation fence as ordinary Git writes, including when another client uses a different operational-state directory. Expired diagnostic lease timestamps cannot let a second writer overtake a live batch; after process death, the kernel releases ownership and the next writer can reclaim the dead process's diagnostic receipt. Lock files live in a private system temporary directory keyed by the brain's canonical path and are not knowledge or operational backup contents. Keep explicit shadow comparison and canonical cutover as separate review steps.

Verification compares every committed Git blob, including attachments, against the preview hashes. Working-tree equality is insufficient: configured Git text or clean filters can transform staged bytes. Such a mismatch leaves a `committed` receipt and returns `migration_git_bytes_changed`; it cannot be marked verified or cut over. Source and backup bytes remain available. Imports and subsequent managed writes append exact-path byte-preservation rules to local Git info attributes before staging. Repository attributes and unrelated local rules remain intact; text normalization, filters, ident expansion, and encoding conversion are disabled only for managed paths.

Canonical session ingestion also records a transcript-hash-bound user-turn map from structured adapter messages. Maintenance uses these relative offsets and validates the exact managed transcript before extraction; it does not infer roles from text labels. Personal Notes and preserved legacy content remain outside this map. Existing records without a map remain excluded from transcript extraction until structured re-ingestion writes one.
